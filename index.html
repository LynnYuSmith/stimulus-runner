How to use the Grating Stimulator

A browser grating presenter for a two-photon rig. Presentation runs entirely in the browser; a small local server (serve.py) only stores your saved protocols as files.

The two screens

  • Open stimulus window ↗ — a clean full-screen canvas; drag it to the mouse's monitor. No second monitor? Fullscreen here ⤢.
  • The operator screen is the cockpit — a live mirror of what the mouse sees is at the right.

The control panel (top → bottom)

  • Status — the live screen state (GREY / BLACK / STILL / MOVING / ▶ run n/N / PAUSED) and whether the stimulus window is connected.
  • Stimulus screen — open the mouse's display.
  • Grey · Black · Abort — the rest states, always one click away.
  • Grating / Field zone / Special stimuli — build the stimulus, then ▶ Present it.
  • Sequence — create and run a queue; load a saved protocol.
  • Detailed Screen & stimulus settings (frame size, marker) sit at the bottom, collapsed — click to expand; you set them once.

Keyboard

  • Space — present the current grating; while a sequence runs it pauses (→ grey) / resumes (replays the interrupted grating).
  • G / Esc — grey · B — black · 1–8 — the eight quick orientations.

Setting a grating

  • Quick gratings present at a preset orientation but honour the moving / still toggle.
  • Custom grating: orientation, motion, waveform, spatial/temporal frequency, contrast, duration.
  • Second grating turns the grating into a plaid: a second grating with its own direction and its own temporal frequency, drifting on its own, and every frame the screen shows the sum of the two. The two are not locked together — set them to different speeds or opposing directions and each still goes its own way. Direction is on the same 0–345° scale as the first grating, so 0° and 180° are the same pattern drifting opposite ways.
  • Plaid sum says what the contrast slider means: per component gives each grating that contrast (so the sum reaches twice it, and above 0.5 the peaks flatten against the screen's range), per plaid keeps the pair within the contrast set and gives each grating half.
  • Start phase and Its start phase say where each grating begins in its cycle, at the frame's top-left corner: 0° a rising zero crossing, 90° a bright peak, 180° the falling crossing, 270° a trough. The two are independent, so setting them apart moves where a plaid's intersections fall at onset. A drifting grating starts there and moves on; a standing one keeps that offset for the whole block. Both are 0 unless set, which is what every block was before, and a non-zero phase shows in the queue as φ.
  • + contrast queues a 4c4s pair: the same grating drifting one way for its duration and then straight back the other way with no grey between (135 then 315, and so on). The second half is automatically marked as the contrast half — 4 pulses instead of 3 — so the recording itself says which is which. + contrast sweep queues four such pairs covering all eight directions, with grey between the pairs and never inside one.
  • + plaid queues one plaid as the form reads it. + plaid sweep queues the pair rotated through all eight directions in 45° steps, the same grid the single-grating sweep uses — the angle between the two gratings stays fixed while the pair turns, so repetition does not adapt the answer (after Lin, Okun, Carandini & Harris 2015).
  • Motion decides what the rate sliders mean. moving: the pattern drifts, and the slider is its temporal frequency. still: the pattern holds and its contrast reverses at the rate you set — 0 is a plain standing grating. Two standing gratings summed is the plaid of the paper this follows; two drifting ones is our own adaptation of it. A standing grating has an orientation and not a direction, so 0° and 180° are then the same stimulus.
  • Set the waveform to sinusoid for a plaid: our default binary wave is there to match the baked stimulus videos, and summing two binary waves gives a three-level chequer rather than the smooth interference pattern a plaid is normally taken to mean. Binary still works and is still recorded faithfully — it is simply a different stimulus from the one the literature calls a plaid.
  • The marker still counts 3 for moving / 2 for still: a plaid is a grating as far as the photodiode is concerned. The second grating is in the log (plaid_direction_deg, plaid_temporal_freq_hz) and in the exported protocol, where the first grating's direction always was.
  • Click any number next to a slider to type an exact value.

Sequences

  • Build a list: + grating, + grey, + black, or a full 0–315° sweep. The header shows the block count and total length.
  • Drag a row by its ⠿ handle to reorder. Run queue plays them in order, each for its own duration.
  • Pause / resume a running sequence with Space or the ⏸ Pause button — pause drops to a grey screen, and resume replays the interrupted grating from the start (it is re-queued, not continued mid-drift). Both are written to the log.
  • Saved protocols live as files in the protocols/ folder — they travel with the folder to any computer. Prepared defaults are included: the four grating sweeps (4s/8s × 1rep/5rep, all 8 orientations), a blitz 3×2 4-flash map, and a bar sweep (4 directions) — pick one from the dropdown and Load.

Field zones (receptive-field mapping)

  • Divide the field into a grid (columns × rows, default 3 × 2) and pick a cell — the grating shows only there; the rest of the field stays grey.
  • The grating's spatial & temporal frequency are computed from the whole screen, so it is the same grating in every cell — only its location changes.
  • + zone sweep queues that grating in every cell in turn — a receptive-field map. ▣ Full field clears the selection.

Special stimuli

  • Blitz — a brief full-field (or single-zone) luminance flash. Set luminance + duration, then ⚡ Flash now, or + blitz to queue it. Honours the selected field zone.
  • Bar sweep — a solid bar drifting across the field in a chosen direction. Set direction, width, luminance, sweep duration; → Sweep now, + bar sweep, or + 4-dir sweep for all four cardinals.

Markers & export

  • A RED corner square pulses at each onset, pulse-count coded: grey = 1, static = 2, moving = 3, and 4 for a grating shown straight after another grating with no grey between — the contrast half of a 4c4s pair (a photodiode reads it).
  • Export protocol writes the played sequence (JSON) to overlay onto the recording; the trial log exports as CSV / JSON.
